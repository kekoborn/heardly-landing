# Лендинг и документация Heardly

**Этот репозиторий — единственный источник правды для сайта.** Правки идут только сюда.
Репозиторий приложения (`kekoborn/Heardly`) сайт больше не содержит: папка `landing/`
в ветке `claude/heardy-docs-sections-47d461` осталась архивом и помечена тегом
`landing-archive-2026-10-21`.

Публикуется GitHub Pages из ветки `main`, из корня, без шага сборки. Живой адрес —
<https://heardly.pro> (`CNAME`).

В репозиторий пушит не только один человек. **Перед любым пушем — `git pull`.**
Форсить нельзя.

## Что где

| Путь | Что |
|---|---|
| `index.html` | лендинг, один файл: разметка, стили и скрипты внутри |
| `docs/` | раздел документации, 27 страниц (26 собираются генератором + `index.html`) |
| `docs/_src/` | **генератор** страниц документации и скрипты съёмки скриншотов — см. `docs/_src/README.md` |
| `legal/`, `privacy/`, `consent/`, `cookies/` | оферта и возврат, политика обработки ПДн, согласие, cookie и аналитика (152-ФЗ) |
| `admin/` | редирект на админку воркера, `noindex` |
| `assets/fonts/` | свои шрифты. Google Fonts не подключаем: по 152-ФЗ шрифты не должны тянуться с чужого хоста |
| `assets/consent.js` | cookie-баннер и запуск Метрики по согласию |
| `DESIGN.md` | дизайн-система лендинга: цвета, типографика, приёмы |
| `PRODUCT.md` | позиционирование и что можно утверждать на сайте |

Отдельной мобильной версии нет: `index.html` адаптивный. Папка `m/` с мобильной версией

## Документация: как править

Тексты 26 страниц лежат в `docs/_src/pages_a.py … pages_e.py`, общая обвязка страницы
(шапка, боковик, подвал) — в `docs/_src/gen.py`. Правка шапки — одна правка, а не 26.

```bash
git pull && python3 docs/_src/gen.py pages_a pages_b pages_c pages_d pages_e
```

После пересборки `git status` должен показывать ровно то, что вы меняли в `pages_*.py`.
Если вы ничего не меняли, а файлы изменились — значит кто-то правил `docs/*.html` руками
мимо генератора, и расхождение надо сначала разобрать, а не затирать.

Генератором **не** собираются `docs/index.html`, `docs/docs.css`, `docs/docs.js` —
их правят напрямую. Карта разделов живёт одним списком в `docs.js`: боковик и
«предыдущая / следующая» строятся из него сами.

Подробности, грабли и съёмка скриншотов — `docs/_src/README.md`.

## Что связано с бэкендом

Форма оплаты на `index.html` бьёт в `POST /create-order` воркера и отправляет вместе
с заказом согласие на обработку ПДн:

```js
consent: { version: CONSENT_VERSION, at: <ISO-время> }
```

`CONSENT_VERSION` в `index.html` — это редакция текста на `/consent/`. **Меняете текст
согласия — поднимите версию**, иначе в заказах останется ссылка на старую редакцию.

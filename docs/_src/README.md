# Исходники раздела документации

У сайта нет шага сборки: в репозиторий и на хостинг едут готовые `docs/*.html`.
Эта папка нужна, чтобы 26 страниц имели одинаковую обвязку, а правка шапки или подвала
не превращалась в 26 одинаковых правок руками.

Папка лежит внутри `docs/`, но на страницу не попадает: ни один `.html` на неё
не ссылается. В репозитории есть `.nojekyll`, поэтому GitHub Pages раздаёт и папки
на `_`: файлы генератора доступны по `/docs/_src/`. Ничего закрытого в них нет
(репозиторий и так публичный), но держать это в уме стоит.

## Что где

| Файл | Что |
|---|---|
| `gen.py` | Шаблон страницы (шапка, боковик, подвал) и сборка. Английские `alt` к снимкам — в словаре `ALT_EN` |
| `pages_a.py … pages_e.py` | Содержимое всех 26 страниц: `title`, `lede`, `group` и тело, русское и английское рядом |
| `shots/` | Съёмка скриншотов: `winlist.swift` и `grabpop.swift` ищут окна, `redact_email.py` убирает личные данные с кадров подписки, `restore.sh` возвращает машину в исходное состояние |

`index.html` (главная раздела), `docs.css` и `docs.js` генератором не собираются —
их правят напрямую. Карта разделов живёт одним списком в `docs.js`: новая страница
правит его, боковик и «предыдущая / следующая» строятся из него сами.

## Пересборка

```bash
python3 docs/_src/gen.py pages_a pages_b pages_c pages_d pages_e
```

Перезаписываются только 26 сгенерированных страниц, остальное в папке не трогается.
Без `HEARDLY_DOCS_OUT` страницы кладутся в папку `docs/`, в которой лежит сам генератор,
откуда бы его ни запустили.

После пересборки `git status` должен быть пуст, если контент не правился: генератор
собирает ровно то, что уже опубликовано. Любое изменение в `docs/*.html` — это то,
что вы правили в `pages_*.py`, и его видно построчно.

Каждый `<figure>` в теле страницы генератор разворачивает в пару: русский кадр
и английский с суффиксом `-en`. Поэтому сборка упадёт, если для снимка нет
английского файла в `img/` или нет английского `alt` в `ALT_EN` — это намеренно.

## Заглушки

Незаполненных мест не осталось: адрес поддержки (`support.html`, раздел «Куда писать»)
вписан — `support@kekoborn.ru`, правится в `pages_e.py` на странице `support`.

Если факта не хватает, ставьте `<span class="todo">[нужен факт: …]</span>` и его
английский аналог: маркер намеренно видим на странице, чтобы раздел не ушёл в публикацию
с дырой.

## Съёмка скриншотов

Снимать только по id окна (`screencapture -o -x -l<id>`): `-R` снимает область экрана
вместе с чужими окнами, однажды в кадр попало окно редактора.

- **Светлая тема.** Окно настроек рисуется светлым даже при системной тёмной теме,
  а поповер и панель диктовки следуют системной. Единообразия можно добиться
  только светлой темой.
- **Поповер меню-бара** не открывается фоновыми кликами (это не AX-окно) и закрывается
  при потере фокуса. Рабочий путь: закрыть все окна приложения, затем `open -a <DevHeardly.app>` —
  сработает обработчик повторного открытия; окно слоя 25 ловится через `grabpop.swift`.
  Если открыто окно настроек или истории, поповер не появится.
- **Панель диктовки** требует глобальной горячей клавиши, а синтетические события не доходят:
  у процесса-отправителя `AXIsProcessTrusted` = false. Обход: временно назначить горячей
  клавишей `Tab` (keyCode 48) и послать клавишу в окно приложения — её ловит локальный монитор.
- **Живая расшифровка** запускается без захвата экрана: кнопка «Запись» в разделе
  «Звонки и встречи» окна Истории доступна фоновым кликом.
- **Речь для кадров** подаётся через `say` (русский голос Milena, английский Daniel;
  Albert распознаётся плохо). Микрофон при этом лучше выключить — звук приложений
  даёт чистый текст без эха.
- **Демо-данные вместо своих.** Приложение уводится на отдельную папку расшифровок
  через `transcriptsFolderPath`, чтобы в кадр не попали рабочие разговоры.
- **После съёмки** — `bash docs/_src/shots/restore.sh`: вернёт горячую клавишу,
  вид панели, язык интерфейса, папку расшифровок, микрофон и тёмную тему.
  Значения в скрипте сняты с машины до съёмки, проверьте их перед запуском.
